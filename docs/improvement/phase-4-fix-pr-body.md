# Phase 4 — Fix Workflow & PR Body Quality

> **Severity:** High  
> **Effort:** Small–Medium (1–2 days)  
> **Dependencies:** Phase 3 (fix summary relies on `.fix-summary.md` written by the fix engine)

---

## Problems Being Solved

### Problem 4.1 — PR body is a copy-paste of the issue description

**Current behavior:**

In `app/src/handlers/commands.ts → createAutofixPR()`:
```ts
const prBody = `## Fixes #${issueNumber}\n\n${issue.body}\n\n---\n*Auto-generated by opencode-ai-reviewer*`;
```

In `action/src/fix.ts → runFixIssue()`:
```ts
const prBody = `## Fixes #${issueNumber}\n\n${issue.body}\n\n---\n*Auto-generated by opencode-ai-reviewer*`;
```

Both paths paste `issue.body` verbatim as the PR body. This means:
- The PR reviewer cannot see what the bot **actually did**
- No list of files changed, no approach description, no test plan
- The PR body reads like an issue report, not a fix summary
- Reviewer has to read every commit diff to understand what changed

**Impact:** Reviewers cannot do a meaningful review. The PR body serves no useful purpose.

---

### Problem 4.2 — Fix summary exists but is not used

**Current behavior:**  
The fix agent writes `.fix-summary.md` during `engine.runFix()`. This is read and stored in `FixResult.summary`. But in `createAutofixPR()`, the result's `summary` is **never used** for the PR body — it is silently discarded.

---

## Proposed Solution

### Step 1 — Create a `buildAutofixPRBody()` utility

**File:** `lib/src/utils/pr-body.ts`

```ts
export interface PRBodyOptions {
  issueNumber: number;
  issueTitle: string;
  fixSummary?: string;       // From FixResult.summary (.fix-summary.md)
  filesChanged: string[];
  branchName: string;
  hasTests?: boolean;
  analysisApproach?: string; // Optional: from analysis plan
}

export function buildAutofixPRBody(opts: PRBodyOptions): string {
  const lines: string[] = [];

  lines.push(`## Fixes #${opts.issueNumber}`);
  lines.push('');

  // Fix Summary — primary content
  lines.push('## What Was Changed');
  lines.push('');
  if (opts.fixSummary && opts.fixSummary.trim().length > 0) {
    lines.push(opts.fixSummary.trim());
  } else {
    lines.push('The fix agent applied changes to address the issue. See commit diff for details.');
  }
  lines.push('');

  // Files Changed
  if (opts.filesChanged.length > 0) {
    lines.push('## Files Changed');
    lines.push('');
    for (const f of opts.filesChanged) {
      lines.push(`- \`${f}\``);
    }
    lines.push('');
  }

  // Optional: analysis approach in collapsed block
  if (opts.analysisApproach) {
    lines.push('<details>');
    lines.push('<summary>Implementation Approach (from analysis)</summary>');
    lines.push('');
    lines.push(opts.analysisApproach.trim());
    lines.push('');
    lines.push('</details>');
    lines.push('');
  }

  // Test Plan
  lines.push('## Test Plan');
  lines.push('');
  if (opts.hasTests) {
    lines.push('- Automated tests were run and pass');
    lines.push('- The fix was verified with project lint/typecheck commands');
  } else {
    lines.push('- Please verify the fix manually before merging');
    lines.push('- Run the test suite to confirm no regressions: `pnpm test`');
  }
  lines.push('');

  // Footer
  lines.push('---');
  lines.push('');
  lines.push(
    `*🤖 Auto-generated by opencode-ai-reviewer from branch \`${opts.branchName}\`.*`
  );

  return lines.join('\n');
}
```

### Step 6 — Update PR body when the autofix loop iterates

The autofix loop runs multiple fix iterations but the PR body is only set at creation and never updated. After each iteration, update it with the latest fix summary.

**File:** `app/src/handlers/autofix.ts → handleAutofixLoop()`

After a successful `git push`:

```ts
if (fixResult.summary) {
  try {
    const freshPr = await gh.getPR(prNumber);
    const updatedBody = buildAutofixPRBody({
      issueNumber: freshPr.linkedIssue ?? prNumber,
      issueTitle: freshPr.title,
      fixSummary: fixResult.summary,
      filesChanged: fixResult.filesChanged ?? [],
      branchName: freshPr.headRef,
      hasTests: !!runChecksAfterFix,
    });
    await gh.updatePR(prNumber, { body: updatedBody });
  } catch (err) {
    logger.warn(`Could not update PR body after iteration: ${err}`);
  }
}
```

**File:** `lib/src/utils/github.ts` — Add `updatePR()` method:

```ts
async updatePR(prNumber: number, updates: { title?: string; body?: string }): Promise<void> {
  await this.api(`/pulls/${prNumber}`, {
    method: 'PATCH',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(updates),
  });
}
```

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Fix agent doesn't write `.fix-summary.md` | Fall back to a generic body when `fixResult.summary` is empty |
| `FixResult.summary` discarded before PR creation | Thread it through — `fixResult` is in scope in `createAutofixPR()`, just not used for the body yet |
| PR body update races with GitHub's API | Use `updatePR()` with retry, tolerate failure (log warning only) |
| Summary too long for PR body | Truncate at 65000 chars (GitHub's limit); surface a note in the body if truncated |
