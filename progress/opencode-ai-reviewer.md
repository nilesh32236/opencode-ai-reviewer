## Review
Five independent read-only review lanes were run against the frozen candidate (security, workflow/YAML, shell/process, test-quality, reliability). Every finding that was raised as a blocker was fixed, and each fix was mutation-tested to confirm it is discriminating:
- **Shared path policy polarity.** Extracting the package/publish path policy into one shared `sec001-path-policy.sh` briefly inverted the deny polarity, which would have rejected every legitimate path and re-admitted the whole denylist. Fixed and pinned three ways: direct allow/deny unit assertions, five `create` cases that use an allow-prefix which genuinely admits the path and assert the failure reason, and a single-backslash case (the pattern previously matched only a *pair*).
- **`If-Match` is inert against the real GitHub API.** A live read-only probe showed GitHub returns `200` for a deliberately wrong `If-Match` on `PATCH /issues/{n}` (it only implements `If-None-Match`), and the returned ETag is weak. The full-label-set replace was therefore an unconditional write that could silently drop a label a human added in the same window, including `autofix:skipped`. The publisher now removes exactly one label with the additive `gh issue edit --remove-label` primitive, re-reads the label set, and fails closed if anything else changed. A regression test models the concurrent-write window; a faithful clobbering-replace mutation is killed by it.
- **Compensating restore word-split labels, and was untested.** `jq @sh` output in an unquoted `$(...)` gets field splitting but no quote removal, so a label containing a space was split into extra argv entries and silently created garbled labels. Replaced with a `while IFS= read -r` loop. The fixture also never modelled a concurrent *removal*, so deleting the loop outright was undetectable; the fake now models both a concurrent add and a concurrent removal, and both directions are pinned.
- **Active-review deferral failed open on pagination.** `gh run list --limit 100` with no server-side status filter spends every slot on completed runs, so past 100 runs an in-flight review fell off the page and the publisher would merge. Now queries each non-terminal status (`queued`, `in_progress`, `requested`, `waiting`, `action_required`) server-side, so the filter cannot be defeated by pagination.
- **Comment-triggered `/fix` accepted any GitHub user.** `ai-review.yml`'s `fix-issue` job runs a write-permissioned, secret-bearing fix loop and had no `author_association` guard, unlike its sibling `autofix` job. Added the same `OWNER`/`MEMBER`/`COLLABORATOR` check (issue #540).
- **`BASH_ENV` was unset on the provider-credential staging steps.** These are the steps on the SEC-001 path that hold a raw provider secret, and each one neutralised it. Now pinned, with a test asserting every provider-key staging step in those two workflows sets `BASH_ENV: /dev/null`.
- **Test-harness false greens.** The behavioural half of the suite aborted on the first failure, dumped all `expect_fail` diagnostics to one shared `/tmp` path, and asserted only "exit != 0". It now runs every case, reports all failures with a count, and provides `expect_fail_matching` for cases that must fail for a specific reason. (The static workflow/workflow-matrix block is still a single fail-fast program: a broken assertion there stops the run before the behavioural half, with a traceback rather than a named failure.) The merge-gate matrix was strengthened so the `pending` and `skipped` cases reach the branches they claim to test, and the gate exit code is asserted exactly (2 for usage errors, 1 for deferrals).
- **Scratch cleanup leaked on every path, not just rejections.** `trap ... RETURN` never fires on `exit`, and the replacement per-function `EXIT` traps were armed on function-`local` variables that are out of scope by the time the script reaches EOF, so the cleanup silently became `rm -f -- ''`. Every `create`, `status`, `wrap` and `validate-package` invocation leaked its scratch files. Replaced with a single script-scope scratch registry and one exit trap installed before any `mktemp` can run, with regression probes that each build a real fixture, several of them pinning the exact rejection reason with `expect_fail_matching`, so a fixture cannot pass by failing earlier than the code it claims to test. `create` is probed on both the success and rejection paths and `wrap` on success; `status`, `validate-package` (two distinct rejection shapes) and `validate-status`/`validate-wrap` on rejection. The publisher, verifier and trusted publisher are separately probed for removal of their private temp root.
- **The publish job could never run.** The finalizer writes the status artifact directly into its `--output` directory, but the publish job read a `status-artifact/` subdirectory that no producer ever created, so `publish` and `trusted-fix` were unreachable. Fixed, with a test that derives the finalizer's output directory from the workflow and asserts that the finalize upload path, the publish download path, every publish-side read of `status.json`, and every `validate-status --artifact` path all name that same directory.
- **`gh run list --status` rejected one of the queried values.** The active-review deferral asked for `pending`, which is not in gh's `--status` enum, so the query aborted and took the merge path down. The set is now exactly gh's non-terminal statuses, and a test cross-checks the queried values against `gh run list --help` when gh is available.

## Residuals and scope
- Provider process groups contain ordinary descendants, but arbitrary model/gate code that calls `setsid` can escape; full cgroup/systemd containment is not claimed.
- The pre-existing self-improvement workflow still runs its model/repair steps as the default runner UID. SEC-002's issue explicitly documents OpenCode subprocess credential inheritance and does not claim full sandboxing; migrating that separate workflow is not part of this repair.
- A verified conflict-resolution patch is published as a commit directly onto the PR's own head branch, with no green-check gate and no human approval, because it is a source change rather than a merge. It is bounded by the shared path policy, the artifact sha256, two live head/label re-reads immediately beforehand, and a `--force-with-lease` push, so it cannot clobber a concurrent push; nothing is merged. No further mutation of that PR follows in the run; the result loop continues with the remaining entries, each independently re-checked against its own pinned head, and the PR's new head must be re-verified from scratch on the next run. An earlier revision held these patches for manual review with a comment and `autofix:needs-manual-review`; that marker was dropped, so a conflict-resolution push is currently not surfaced to a human beyond the commit itself.
- `BASH_ENV: /dev/null` guards every step that stages a provider key on the SEC-001 path (the hourly orchestrator and self-improvement workflows, which the suite asserts). `upstream-monitor.yml` still holds provider keys in two steps without the guard; that workflow is outside this repair and is a follow-up.
- **`shell: /bin/sh` killed the hourly orchestrator on `main`.** `/bin/sh` is not a valid Actions `shell:` value: the runner accepts only the built-ins (`bash`, `sh`, `cmd`, `powershell`, `pwsh`) or a `{0}` template, so the step was rejected with `Invalid shell option` before the script ran. Every scheduled run on `main` since PR #785 failed in Discover, which meant the whole autonomous pipeline was dead. This shipped because nothing in the repository inspected the `shell:` key at all: the runner rejects the value before any script runs, so a syntax check of the `run:` body — or a careful read of the workflow — can both pass while the job is dead on arrival. Both the hourly orchestrator and self-improvement workflows are corrected to the `sh` built-in (the same `/bin/sh` dash interpreter on ubuntu runners), and a test now asserts every `shell:` value in every workflow, job default, and composite action is a runner built-in or a `{0}` template, failing loudly if it cannot parse rather than silently passing.
- GitHub comment/label operations remain externally non-atomic where no conditional API exists. The pending-label removal is now a single-label additive delete, so it cannot clobber concurrent labels; the remaining `autofix:skipped` (issue spam) and `autofix:needs-manual-review` (self-improvement) writes are additive, so they cannot clobber a concurrent label; the issue-side writes are bracketed by a content fingerprint, and the PR-side skip write is bracketed by live head/ref/base and skip-label re-reads plus a marker re-check (content fingerprints do not exist for PRs).
- In issues mode the verifier checks the answer's schema, size, encoding, and run/issue binding but does not run the build/test/lint gates, so an answer comment is posted by a bot without a human in the loop. The run/issue binding plus the marker make it idempotent, and re-applying `analysis:needs-input` re-opens the question.
- A model-classified `spam` result adds `autofix:skipped` to a human's issue with no human gate. This is fail-safe (it stops automation) and human-reversible.
- The `active-review` deferral queries the Actions API per non-terminal status and matches either the pinned head SHA or the synthetic `<n>/merge` ref. It is still a best-effort race-avoidance heuristic: a review run that starts after the query is not observed. The authorization barrier is the pinned verified head, the required green checks, human approval bound to that head, and `--match-head-commit`.
- `ai-review.yml`'s `review` and `notify-merged` jobs predate this work: `review` checks out the synthetic merge ref and runs the PR's own action code, and `notify-merged` inherits `contents: read` while calling APIs that need write scopes. Both are unchanged here and warrant their own PR.
- A compact cross-job retry ledger and dependency-install cache remain follow-up design work, not implemented in this bounded repair.
