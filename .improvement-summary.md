## What Changed and Why

### 1. CI Workflow Hardening (` .github/workflows/ci.yml:1 `)

**Why:** 2026 best practices require least-privilege permissions and `fail-fast: false` in matrix builds. Without these, a failure on Node 24 hides the result on Node 22, and the workflow runs with overly broad default permissions.

- Added workflow-level `permissions: contents: read` and per-job `permissions: contents: read` for `test`, `coverage`, `benchmarks` jobs — least-privilege hardening per GitHub Actions security guidance.
- Added `strategy.fail-fast: false` to the `test` matrix (Node 22 vs 24) so both versions report independently. Previously the default `fail-fast: true` cancelled the Node 24 run if Node 22 failed, hiding version-specific regressions.
- Added explanatory comment for the permissions block.

### 2. Circuit Breaker Jitter & Observability (` lib/src/utils/circuit-breaker.ts:24 `)

**Why:** Self-healing pipelines with many breakers sharing a downstream (GitHub API) suffer thundering-herd recovery when all breakers use the same deterministic cooldown. Research highlighted jittered cooldowns as a standard remediation.

- Added `jitterRatio` option (`lib/src/utils/circuit-breaker.ts:32`) — effective cooldown becomes `cooldownMs * (1 + rand * jitterRatio)`. Default 0 (backward compatible), recommended 0.15–0.25 for shared downstreams.
- Added `effectiveCooldownMs` tracking and `computeEffectiveCooldown()` helper (`lib/src/utils/circuit-breaker.ts:234`) that applies jitter at each trip to OPEN.
- Enhanced `transitionState()` (`lib/src/utils/circuit-breaker.ts:107`) to use `effectiveCooldownMs` instead of fixed `cooldownMs`.
- Added `getRemainingCooldownMs()` (`lib/src/utils/circuit-breaker.ts:151`) for dashboards and to avoid busy-polling an OPEN circuit.
- Enhanced OPEN error message to include both effective cooldown and remaining time.
- Fixed `reset()` to restore `effectiveCooldownMs` to base value.
- All new public methods and helpers have JSDoc so `pnpm doc:check` stays green.

### 3. EventBus Configurability (` lib/src/event-bus/bus.ts:6 `)

**Why:** Hardcoded `SUBSCRIBER_CONCURRENCY = 10` and `SUBSCRIBER_TIMEOUT_MS = 600_000` prevent operators from tuning under load (e.g., lower concurrency when LLM subscribers contend for tokens).

- Extracted constants to `DEFAULT_SUBSCRIBER_CONCURRENCY` / `DEFAULT_SUBSCRIBER_TIMEOUT_MS`.
- Added `EventBusOptions` interface (`lib/src/event-bus/bus.ts:9`) with `concurrency` and `subscriberTimeoutMs`.
- Added `constructor(options?: EventBusOptions)` — fully backward compatible (defaults unchanged).
- `publish()` and `executeSubscriber()` now use instance fields `this.concurrency` / `this.subscriberTimeoutMs`.
- Added `getSubscriberCircuitState(name)` (`lib/src/event-bus/bus.ts:260`), `getConcurrency()`, `getSubscriberTimeoutMs()` for observability and testing.

### 4. New Skill: Self-Healing (` .agents/skills/self-healing/SKILL.md `)

**Why:** No dedicated skill existed for self-healing patterns; future autonomous agents lacked a single reference for retry, circuit breaker, EventBus, and CI resilience conventions.

- Created `.agents/skills/self-healing/SKILL.md` covering: architecture table, circuit breaker usage with `jitterRatio` and `countHttpError`, retry with `withRetry`/`withRetryAndTimeout`, EventBus tuning, workflow self-healing patterns (bounded retries, confidence thresholds, cost guardrails, least privilege, `fail-fast: false`), verification checklist, and file references.
