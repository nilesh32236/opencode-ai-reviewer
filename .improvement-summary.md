# Self-Improvement Summary

## Improvement: Honor server `Retry-After` hints in the retry layer

### What I researched
Web searches (before making changes):
- "GitHub Actions self-healing CI/CD autonomous agent best practices 2026"
- "TypeScript AI code review tool architecture patterns"
- "GitHub REST API rate limit 429 Retry-After header seconds best practice retry"

Key finding from GitHub's official REST API docs (`troubleshooting-the-rest-api` /
`best-practices-for-using-the-rest-api`): on a rate-limit error (403/429) you
**should not retry until the `Retry-After` header's seconds have elapsed**; if
`x-ratelimit-remaining` is 0, wait until `x-ratelimit-reset`. Repeated rapid
retries can trigger secondary rate limiting or get the integration banned.

Context7 MCP docs checked:
- `better-sqlite3` (transaction usage)
- `@actions/core` (error handling and retry)
- GitHub Actions website docs (rate-limit/Retry-After behavior)

### What I changed and why

1. **`lib/src/utils/retry.ts`**
   - Added `maxRetryAfterMs` option to `RetryOptions` (default: 120000ms / 2 min)
     so a server-provided hint can be clamped independently of the exponential
     backoff cap.
   - `withRetry` now extracts a Retry-After hint from the thrown error and waits
     **at least** that long before retrying, taking precedence over pure
     exponential backoff. Added helper functions `extractRetryAfterMs`,
     `toRetrySeconds`, `getRetryAfterHeader`, and `parseRetryAfterHeader` that
     support both the explicit `retryAfterSeconds` property and the `retry-after`
     response header (delta-seconds and HTTP-date formats).
   - The warning log now labels retries that honored the hint
     (`Retry-After hint honored`), making the behavior observable.
   - Previously 429s were retried after only ~1-2s of backoff, which contradicts
     GitHub's documented guidance and risks secondary rate limiting.

2. **`lib/src/utils/github.ts`**
   - `api()` and `graphql()` now attach the response `headers` to thrown errors so
     the shared `withRetry` utility can read `Retry-After` on 429 responses. This
     applies to both REST and GraphQL paths automatically.

3. **`lib/tests/retry.test.ts`**
   - Added 6 tests covering: `retryAfterSeconds` property, `Headers` instance
     header, plain-object header record, HTTP-date format, clamping at
     `maxRetryAfterMs`, and fallback to exponential backoff when no hint exists.
