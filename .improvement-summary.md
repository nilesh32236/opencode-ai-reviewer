# Improvement Summary — CircuitBreaker Failure Classification & Observability

## What I researched

- "GitHub Actions self-healing CI/CD autonomous agent best practices 2026"
- "TypeScript AI code review tool architecture patterns retry circuit breaker"
- "Node.js ESM monorepo pnpm build optimization"

Key takeaways applied here: 2026 guidance for AI/CI agent reliability explicitly recommends that
circuit breakers **classify failures** — *"Trip on: timeouts, 5xx responses, connection refused.
Do NOT trip on: 4xx responses (client errors), validation failures"* — and that operators should
*"Log every state transition. Alert on open circuits. Track: failure rate, trip count, recovery
time"*. The existing `CircuitBreaker` counted every error identically and exposed only
state/failureCount/successCount, which made deterministic client errors trip the circuit and gave
no visibility into cumulative trip/recovery behavior.

## What I changed and why

### 1. `lib/src/utils/circuit-breaker.ts`
- **Added `shouldCountFailure` option**: an optional `(err: unknown) => boolean` predicate that
  decides whether a thrown error counts toward the failure threshold. Rejected errors are still
  re-thrown to the caller but never increment `failureCount` or influence circuit state. A
  throwing classifier is handled gracefully (warn + count as failure).
- **Added `countHttpError` exported classifier**: for HTTP-backed callers. Counts 5xx, 429 (rate
  limits, which indicate the caller is hammering the API), and unknown/network errors; does NOT
  count deterministic 4xx client errors (400, 404, 422, …).
- **Richer metrics**: `getMetrics()` (and all lifecycle-hook payloads) now include cumulative
  `callCount` and `tripCount`, plus `lastFailureAt` / `lastSuccessAt` timestamps. Cumulative
  counters survive `reset()`, giving failure-rate, trip-count, and recovery-time visibility.

### 2. `lib/src/utils/github.ts` and `lib/src/utils/gitlab-adapter.ts`
- Wired `shouldCountFailure: countHttpError` into both API adapters' circuit breakers so a
  deterministic 4xx client error (e.g. a `404` on a stale path) no longer contributes to tripping
  the circuit, while genuine 5xx/rate-limit failures still do.

### 3. `lib/tests/circuit-breaker.test.ts`
- Updated the two exact-match hook assertions to `expect.objectContaining(...)` for the expanded
  metrics payload.
- Added tests for: cumulative `callCount`, `tripCount` on each open, `lastFailureAt`/`lastSuccessAt`
  timestamps, `shouldCountFailure` (rejected errors don't count/trip, accepted errors still do,
  errors are re-thrown regardless, throwing classifier is tolerated), and the `countHttpError`
  classifier across status classes.

### 4. `.agents/AGENTS.md`
- Documented the new `shouldCountFailure` option, the `countHttpError` classifier, the enriched
  `getMetrics()` observability fields, and that `GitHubHelper`/`GitLabAdapter` already use the
  classifier.
