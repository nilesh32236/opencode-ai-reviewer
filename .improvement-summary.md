## What I changed and why
1. **Self-healing fix — `withRetryAndTimeout` honors outer cancellation** (`lib/src/utils/retry.ts`):
   - Previously the outer `options.signal` was only checked *between* retries; the in-flight attempt received only the per-attempt timeout signal, so cancelling mid-operation had no immediate effect.
   - Now the per-attempt signal is combined with the outer signal via `AbortSignal.any()` (with a manual event-wiring fallback for runtimes without it), preserving which source fired first via the abort `reason`.
   - Per-attempt timeout now aborts with a `TimeoutError`-named `DOMException` (was a generic abort), so callers can distinguish deadlines from deliberate cancels.
   - `withRetry` now fails fast on cancellation: an aborted outer signal or an `AbortError` from the operation itself is re-thrown immediately instead of burning retries (this also removed a misleading "Retrying... User cancelled" warning).
2. **Prompt engineering — hardened `error-handling-resilience` audit prompt** (`prompts/audit-categories/error-handling-resilience.md`):
   - Added Cancellation & Timeouts section (`AbortSignal.any()` composition, `TimeoutError` vs `AbortError`, `throwIfAborted` checks), Retry & Backoff additions (Retry-After clamping, fail-fast on deterministic errors, POST-only-on-429 idempotency rule), and a Self-Healing Guardrails section (bounded ~3 attempts, scope limits, auditable trail, verify-with-same-gates).
3. **Tests** (`lib/tests/retry.test.ts`): added "aborts the in-flight attempt when the outer signal fires" and "throws immediately when the outer signal is already aborted".
